# yuto-matsui.com カードの情報設計

2026-09-12。対象はJP/ENのExpertise・Experience・Off hours。本文・既存写真・各言語のテーマカラーを保持する。

## 参考と採用理由

- [Linear Features](https://linear.app/features)：主役のビジュアルを明確にし、カードの外枠と説明文を安定させる構成。写真と説明文の役割分担に応用。
- [Stripe Finance Automation](https://stripe.com/use-cases/finance-automation)：本文と図版の領域を分け、複数の画面の前後関係でつながりを表す構成。写真・立体・本文の描画と余白を分離する判断に応用。
- [Apple iPhone](https://www.apple.com/iphone/#feature-card-gallery)：カテゴリ、見出し、主役のビジュアルを一つのカード内で明確にする構成。3分野を同時に比較できる配列と、揃った本文・写真の位置に応用。

各サイトの実表示を参照した独自の再構成であり、素材・ブランド色・コピーは流用しない。参考サイトのアニメーションやhover拡大は採用しない。

## 3Dの役割

Expertiseは既存写真を唯一の主役のビジュアルとし、「大きな写真 → 見出し → 本文」の順で構成する。写真と情報が重複していた3Dイラストは、ユーザーの指示に従い撤去する。イラスト用の画像・生成処理・専用余白も残さない。

全9カードの写真には共通の静的な支持面を設ける。CSSの3D面は写真と本文の背後に独立した描画領域として配置し、写真と本文自身は通常のHTMLとして表示する。カード全体を傾けたり、ポインター・タップで拡大したりしない。

## セクション間の強弱

Expertiseは専門性を把握するための3列構成。ENも3分野の一覧性を優先し、独自のセリフ書体・パール系背景・アクセント色を保つ。900px以下は1列。写真を先頭に置く順序と余白はMobileでも共通。

Experienceは年数・分野・Focusの読み取りを優先する。Off hoursは写真と短い本文を主役とし、拡大ビューアーを設けない。FRAGMENTSとProductsの既存3D実装は保持し、新しいカードには常時動く演出を追加しない。ENのFRAGMENTSはExperienceとStatementの間を維持する。

## 初期表示と確認

写真はタップやクライアント初期化を待たずHTMLから読み込む。元のファイルをそのまま使うため、既存写真の合計転送量は変わらないが、eager指定によって読み込み開始は早まる。画像のcompleteだけでは3D合成による欠落を検出できないため、WebKitで操作前の写真・本文を実描画で確認する。対象JP/ENのDesktop/Mobile、hover/tap後の静止、横はみ出しを限定して検証する。
