# 未来戦略ライブラリ Phase 3 要件定義

最終更新: 2026-07-17  
対象: 登録UI・条件付き項目・同意記録・資格判定・二重登録防止

## 1. 目的

現行GASの主要な登録判定を、質問文の文字列検索ではなく型付き入力と純粋関数で再現する。Phase 3ではGoogle認証、DB、Drive、Gmailへ実接続せず、後続フェーズが同じ判定契約を利用できる状態を完成とする。

責務境界を次のとおり固定する。Google OAuthは大学Workspaceアカウントの
本人操作、`email_verified`、許可`hd`、`sub`を確認する認証層である。
薬学部、学年、学籍番号、学生・教員等の承認分岐はフォーム入力を使う
内部資格判定層であり、OAuthから推測または置換しない。

同じ許可`hd`を持つ組織ユーザーは、学生・教員の区別なくOAuth認証層を
通過する。この変更は内部資格判定層の自動承認、個別確認、対象外条件を
変更しない。内部資格判定を変更する場合は、共通JSON判定ケースの明示的な
改版と運営者承認を必須とする。

## 2. Phase 3の安全境界

- 現行Googleフォーム、GAS、`future-strategy-library/`のCTAは変更しない。
- 認証情報、個人情報、フォーム入力を外部へ送信しない。
- Googleアカウントは明示された検証用モックだけを使用する。
- フロントエンドの判定表示は入力支援であり、本番の権威はFastAPIとする。
- `hd`の実値、規約本文、プライバシー本文、保存期間が確定するまで本番送信を有効化しない。

## 3. 入力項目と条件表示

| 項目 | 学部生・修士 | 博士課程 | 教職員・大学担当者 |
| --- | --- | --- | --- |
| 氏名 | 必須 | 必須 | 必須 |
| 在籍区分 | 必須 | 必須 | 必須 |
| 所属学部・部門 | 必須 | 必須 | 必須 |
| 学年 | 必須 | 任意・非表示 | 不要・非表示 |
| 学籍番号 | 必須 | 任意・非表示 | 不要・非表示 |
| 利用条件同意 | 必須 | 個別確認のため任意 | 問い合わせのため任意 |
| 個人情報取扱い同意 | 必須 | 必須 | 必須 |
| 質問・意見 | 任意、最大1000文字 | 同左 | 同左 |

在籍区分を変更した場合、不要になった学年と学籍番号はクライアント状態から削除する。

## 4. 正規化

学籍番号は次の順で正規化する。

```text
Unicode NFKC
-> 前後空白除去
-> 大文字化
-> ^(PP|PL|MP)[0-9]{5}$
-> PP00000は無効
```

内部空白は削除しない。氏名は前後空白だけを除去し、メールはNFKC、前後空白除去、小文字化を行う。

## 5. 判定優先順位

1. 未認証または必須入力不足は`not_ready`。
2. トークン不正、メール未検証、許可外`hd`、北里大学外メールは`ineligible`。
3. 学部生・修士課程の学籍番号不正、`PP00000`は`ineligible`。
4. 同一人物の同一内容が既に存在する場合は`already_registered`として冪等に扱う。
5. 既存登録と入力が競合する場合は`manual_review`。
6. 博士課程、教職員等、非学生大学メール、薬学部以外は`manual_review`。
7. 次の条件をすべて満たす場合だけ`approved`。

```text
有効なGoogle認証
AND 検証済みメール
AND 許可されたhd
AND 学生メールドメイン
AND 在籍区分が学部生または修士課程
AND 所属学部が薬学部
AND 学籍番号がPP / PL / MP + 数字5桁
AND 学籍番号がPP00000ではない
AND 利用条件に同意
AND 個人情報取扱いに同意
AND 必須項目が完全
```

## 6. 二重登録防止

Phase 3のUIでは同一画面内の連続送信をモックで検知する。本番ではクライアント判定を信用せず、`google_sub`、正規化メール、正規化学籍番号のDB一意制約とトランザクションで保証する。

- 同一人物・同一内容: 既存結果を返し、Drive・メール処理を再実行しない。
- 同一人物・異なる内容: `manual_review`へ送り、既存レコードを自動上書きしない。
- 二重クリック: 同じ冪等キーの処理を1回だけ受理する。

## 7. 同意記録

Phase 3の固定値は検証用であり、正式本文確定後に差し替える。

```text
terms_version = phase3-draft-2026-07-16
privacy_version = phase3-draft-2026-07-16
```

本番保存時は真偽値だけでなく、各バージョンと同意日時をFastAPI側で記録する。クライアント時刻は正本にしない。

## 8. 受け入れ条件

- TypeScriptとPythonが同じJSON判定ケースを通過する。
- 薬学部かつ有効なPP/PL/MP形式だけが自動承認候補になる。
- 博士課程、教職員等、薬学部以外が個別確認になる。
- 無効学籍番号、対象外ドメインが対象外になる。
- 条件付き項目、同意条件、判定理由がUIへ反映される。
- DesktopとMobileで送信完了まで操作できる。
- 既存静的サイトのファイルがビルド前後で完全一致する。

## 9. Phase 3に含めないもの

- 実Google IDトークン検証
- Neon/PostgreSQL保存と一意制約
- Drive権限付与、Gmail送信
- 管理画面、CSV、既存名簿移行
- 本番CTA切り替え

これらはPhase 1/2またはPhase 4以降のゲートを満たした後に接続する。
