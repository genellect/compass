## 2026-09-13: 3D ON/OFFと起動判定の修正

- 旧3Dで55fpsを確認した後、新3Dでもほぼ60fpsを要求する二重判定が、描画可能なIris Xeを除外していた。二重判定を撤去し、約30fpsの安定描画を許容した。未達時は3段階で描画負荷を下げて再判定する。
- 同じWindows PC / Intel Iris Xe / Codex in-app browserの通常時計で、自動起動とLibraryへの実移動を確認した。初期構図の描画呼び出しは117から64、三角形は438,170から237,726へ減少（影の再描画を含む集計）。GPUの実使用量や全構図の性能保証ではない。
- 開発サーバーに対する実時計の専用テストで、保存設定のないPCの自動ON、OFFで新旧Canvasが0になること、OFFの再読み込み保持、再度ONにできることを確認した。時計・GPUタイマーの上書きはしていない。
- 新しいOFFは旧3Dを再開せず静止表示とする。iPad・Mobile・独立サイトのソースは変更しない。
- 独立した切替CTA・3つの追加行き先CTAを撤去した。既存ヘッダー内へON/OFFを統合し、既存CTAとナビゲーションから各室へ移動する。室内の最終CTA・外部リンク・別タブ操作は元のリンク先を維持する。
- 最終buildの専用8件を実行し、9室の本文・リンク・コントラスト、移動・履歴・context喪失、音声・動画・除外条件、901px等でのヘッダー内の収まりを確認した。Windowsの終了処理が待機したため中断し、その実行全体を正常終了したgate合格とは扱わない。
- 終了処理に依存しない独立サーバーで最後の実時計ケースとMobile・iPad・reduced motionを再確認し、4件が43.2秒で正常終了した。自動ON、既存ヘッダーCTAからLibrary入室、室内の元リンク、OFFで新旧Canvasが0、再読み込み保持、再ONが合格。実機iPadではなくブラウザーエミュレーションである。
- TypeScript、Vitest 5件、最終build、static export、公開ソース634ファイル、維持文書リンク122件が合格。保護対象ソースとbaselineは変更していない。モード管理の個別gzipは4,421 bytes。
- この修正では無関係な広域279件を反復せず、型検査・5件の単体・起動/操作/除外端末に関係するブラウザー検証と配信用buildを行う。下記の広域結果は前版の記録として保持する。

## 配信と描画

`report-assets.mjs`による測定:

| 項目 | 結果 |
| --- | ---: |
| 最初の空間に必要な新規素材 | 7,131,279 bytes |
| 新規配信素材全体（動画・音声を含む） | 9,180,260 bytes |

| 1440×900のHero / 描画呼び出し | 117 |
| 同構図の三角形（shadow等を含むrenderer.info） | 438,170 |
| 同構図のGPU資源推定 | 499.1 MiB |

素材容量は既存v3モデル/HDRやNext共通runtimeを除く。cold状態での手動起動では既存モデルの追加取得も発生する。モード管理のgzipは独立したモジュール測定であり、配信の実測差分とは区別する。

GPU資源はテクスチャ・geometry・描画bufferの推定値であり、ドライバーの実使用量ではない。経路途中の複数モデルの入れ替えを含むピークは未確定。

## 性能と品質の未検証事項

前版はWindows / Intel Iris Xeの起動基準を満たせず復帰した。上記の修正版では同PCの実時計による自動起動を確認した。これは高性能PCや実機ブラウザの60fps認定ではない。機能fixtureでは時計を固定しているため、その60fpsを性能実績として用いない。

高性能PCでの15分以上の継続測定、Firefox/Safari、実機iPhone/Android/iPad、全9室の自由視点に対する最終的な照明・材質・視覚品質の承認は未完了。

現在のPreviewは情報設計・移動・表示切替を確認する制作段階の版であり、「実写級の完成版」ではない。追加の制作と、今回のPreviewに対する明示承認なしにProductionへ公開しない。
